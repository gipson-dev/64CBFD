## Checked Loop Obligations

The [instruction-level checker](../../tools/experiments/game_quad_edge_loop_values.py)
executes the actual linked candidate and retail words. For each valid kind
0..2 it checks all four outer edges, empty and positive paths, and one
arbitrary symbolic inner index on both continuation and exit: **24 outer
cases and 24 induction-step obligations**. The 1,000-instruction safety
bound rejects an unrecognized control path; it is not the iteration bound.

The base case is j=0. The step compares j'=j+1, the exact selected X/Z
count, and the likely-delay-slot transfer into F18. For
0<=j<count<=INT_MAX, the signed increment cannot overflow. Live cursor,
next vertex, color pointer, reciprocal, scale, half, base, width, lifetime,
preset and midpoint-byte homes must agree. Each continuing stream must
preserve its own per-edge snapshots, not merely agree with the other stream.
Saved ABI state, all 33 copied table bytes, incoming homes and the initial
range limit are independently invariant, including on exit paths. Both
empty and positive final edges restore the incoming O32 ABI.

Intermediate GPRs and FPRs are arbitrary at each new edge. Every inner step
gets fresh external vertex memory. The **three zero-input RNG calls** and
**all 31 physical factory argument words** compare symbolically, including
full duration/context words and the correct byte extractions. Providers get
arbitrary caller-saved GPR/FPR/HI/LO results, may overwrite outgoing register
homes, and advance external memory after each call. This is stronger than
assuming the particular RNG's benign HI/LO behavior, but is still a framed
software model rather than actual provider/hardware execution.

The contract is deliberately explicit: valid vertices disjoint from the
private frame/incoming homes; kind 0..2; defined signed conversions;
count<=0 or count>=2; nonzero unsigned divisors on executed paths; ordinary
nonvolatile memory without asynchronous writes. Providers cannot inspect
unescaped locals or incoming homes. FP operations are uninterpreted terms
with ordered operands except **finite non-NaN addition commutation**.
That algebraic property is an explicit assumption, **not an SMT/IEEE
verification result**. The checker preserves the FP expression multiset
but proves no raw FCSR/cause, exception, NaN-payload, fault-order or private-
RAM equivalence. Singleton/zero-divisor/stack-poison guest cases remain
separate literal-code requirements before any future normalization.
